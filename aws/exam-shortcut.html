The Exam Shortcut

← AWS prep home

SAA-C03 stems are long, but they are built out of a small vocabulary. A handful of phrases — “consolidated billing”, “must not traverse the public internet”, “least operational overhead” — point at one service almost every time they appear. This page is that vocabulary: the trigger on the left, what to think on the right.

Use these as tiebreakers, not as answers. A trigger phrase narrows four options to two; the rest of the stem — the constraint on cost, latency, downtime, or operational effort — picks between them. Skipping the stem is how a shortcut becomes a wrong answer.

Security, Identity, and Compliance

Roughly a third of the exam. Most of these stems name a governance boundary — an account, an OU, a directory, an audit trail — and the boundary is the giveaway.

When you see… Think…
Manage many AWS accounts centrally AWS Organizations One organization is the only place accounts are created, grouped, and governed together.
Consolidated billing / one invoice across accounts AWS Organizations Consolidated billing is an Organizations feature; usage also pools for volume tiering.
Organize accounts into organizational units (OUs) AWS Organizations OUs are the grouping unit policies attach to.
Organization-wide guardrail nobody can exceed, not even an account admin Service control policies (SCPs) AWS Organizations An SCP caps the maximum permissions in an account; it never grants anything, and it does not apply to the management account.
Stand up a governed multi-account landing zone and vend new accounts AWS Control Tower Sits on top of Organizations and automates the baseline: OUs, guardrails, log archive, account factory.
Employees log in once and reach many AWS accounts AWS IAM Identity Center Workforce SSO across every account in the organization, from one portal.
Users already live in Active Directory or an external SAML/OIDC identity provider AWS IAM Identity Center Point it at the corporate directory as the identity source instead of re-creating users as IAM users.
Sign-up and sign-in for your own application's users Amazon Cognito user pools A user pool is the app-user directory that authenticates and issues tokens. Workforce access is IAM Identity Center; app users are Cognito.
App users need to call AWS APIs directly (upload to their own S3 prefix) Amazon Cognito identity pools An identity pool trades a verified login for temporary AWS credentials from STS.
Short-lived credentials, role assumption, cross-account access AWS STS STS is the machinery behind every role assumption; credentials expire in minutes to hours.
EC2 instance or Lambda function needs AWS permissions without stored keys IAM roles Attach a role; the credentials are temporary and rotated for you. Long-lived access keys on an instance are always the wrong answer.
Grant another account access to one bucket or key without creating a role Resource-based policies AWS IAM A bucket or key policy can name an external principal directly — the second cross-account path alongside AssumeRole.
Record who called which API, when, and from where AWS CloudTrail The account-wide API audit trail. "Who did this?" is always CloudTrail.
Show a resource's configuration history, or detect drift from a rule AWS Config Config records configuration state over time and evaluates it continuously. "What did this look like last Tuesday?" is Config.
Automatically remediate a non-compliant resource AWS Config Config rules can attach remediation actions that fix the resource when it drifts.
Detect compromised credentials, crypto-mining, or unusual API and DNS activity Amazon GuardDuty Continuous threat detection over CloudTrail, VPC Flow Logs, and DNS logs — no agents to deploy.
Find and classify PII or other sensitive data sitting in S3 Amazon Macie Macie is the S3-specific sensitive-data discovery service.
Block SQL injection, XSS, bad bots, or rate-limit one source IP AWS WAF Layer-7 request filtering in front of CloudFront, an ALB, or API Gateway.
Large sustained DDoS attack, 24/7 response team, protection from scaling charges AWS Shield Advanced Standard is free and always on; the response team and cost protection are what Advanced buys.
Encryption keys you create, control, audit, and rotate AWS KMS One key policy per key, default-deny even for the account root, and automatic rotation for symmetric keys.
Database password or API key that must rotate automatically AWS Secrets Manager Built-in scheduled rotation is the discriminator — plain parameter storage has none.
Free public TLS certificate that renews itself AWS Certificate Manager DNS-validated ACM certificates renew unattended while they stay attached; imported and private-CA certificates do not.
Certificate for a CloudFront distribution AWS Certificate Manager It must be requested in us-east-1 no matter where the origin lives.
Stateful firewall on the instance, allow rules only Amazon VPC Security Groups Return traffic is permitted automatically, so you only open one direction.
Explicitly deny one IP range at the subnet edge Amazon VPC Network ACLs NACLs are the only VPC control with deny rules; they are stateless, so both directions need opening.
One backup policy spanning EBS, RDS, DynamoDB, EFS, and more AWS Backup Central backup plans and vaults instead of per-service snapshot schedules.
Records that must not be deleted or altered for a retention period (WORM) S3 Object Lock Write-once-read-many retention and legal holds for compliance regimes.
Least privilege, MFA on root, stop using root day to day AWS IAM The generic account-hygiene answer whenever a stem describes permissions rather than a specific tool.

Networking and Content Delivery

Two questions decide most of these: does the traffic have to stay off the public internet, and is it HTTP or not?

When you see… Think…
Private subnet needs outbound internet for patching, no inbound NAT Gateway Managed egress. Instances reach out; nothing reaches in.
Reach S3 or DynamoDB privately, at no extra charge VPC Gateway Endpoints A free route-table entry — and only those two services get one.
Reach another AWS or partner service over private IPs, no internet path AWS PrivateLink Interface endpoints put an ENI in your subnet; billed hourly plus per GB.
Connect exactly two VPCs privately VPC Peering One-to-one and non-transitive: three VPCs need three peerings, ten need forty-five.
Connect many VPCs and on-premises links without a peering mesh AWS Transit Gateway Hub-and-spoke with transitive routing; the fix whenever a stem counts VPCs.
See which flows the VPC accepted and rejected VPC Flow Logs Traffic metadata at the VPC, subnet, or ENI level — the answer to "why is this connection failing?"
Encrypted link to on-premises, working within hours, low cost AWS Site-to-Site VPN IPsec over the public internet: fast to stand up, internet-variable performance.
Consistent bandwidth and latency to on-premises, off the public internet AWS Direct Connect A dedicated circuit — and weeks of lead time, which is how stems hint at it.
Private on-premises link that must survive the circuit failing AWS Site-to-Site VPN The standard pattern is Direct Connect as primary with a VPN as the backup path.
Cache HTTP(S) content near users worldwide Amazon CloudFront A CDN: edge caching, TLS, signed URLs, origin shielding.
Static entry IP addresses and near-instant regional failover for TCP or UDP AWS Global Accelerator Two anycast IPs onto the AWS backbone. Non-HTTP traffic or fixed IPs rules CloudFront out.
Send each user to the lowest-latency Region Route 53 latency-based routing DNS-level Region selection based on measured latency, not geography.
Shift a percentage of traffic for a canary or blue/green rollout Route 53 weighted routing Weights split resolution across records; the classic gradual-cutover answer.
Fail over to a standby Region when health checks trip Route 53 failover routing Health-checked primary/secondary records — the DNS half of most DR designs.
Serve or block content based on the viewer's country CloudFront geo restriction Enforced at the edge, before the request reaches the origin.
Route HTTP requests by URL path or hostname Application Load Balancer Layer 7 routing to target groups — including Lambda targets.
Millions of connections per second, TCP/UDP, or a static IP per AZ Network Load Balancer Layer 4, ultra-low latency. Any non-HTTP protocol in the stem means NLB.
Backend must see the client's real source IP without parsing headers Network Load Balancer NLB preserves the source IP; an ALB terminates the connection and passes it in X-Forwarded-For.
Slot third-party firewall or IDS/IPS appliances into the traffic path transparently Gateway Load Balancer The only load balancer whose job is appliance insertion.
Managed front door for REST, HTTP, or WebSocket APIs with throttling and auth Amazon API Gateway Also the answer whenever a stem wants per-client rate limiting on an API.
Data tier must have no path to the internet at all Amazon VPC A private subnet whose route table has neither an internet gateway nor a NAT route.
Choosing between one shared NAT gateway and one per Availability Zone NAT Gateway One per AZ costs more per hour but removes both the cross-AZ data charges and the single-AZ failure mode.

Compute, Containers, and Serverless

Read the operational-overhead clause first: it usually decides between EC2, containers, and functions before any technical requirement does.

When you see… Think…
Run code with no servers to manage, triggered by an event AWS Lambda Billed per millisecond, scales itself, capped at 15 minutes per invocation.
Job runs longer than 15 minutes AWS Fargate The Lambda ceiling is the trap; run it as a container task (or an AWS Batch job) instead.
Containers with no instances to provision or patch AWS Fargate "Least operational overhead" plus containers is Fargate almost every time.
Docker orchestration with the least AWS-specific complexity Amazon ECS AWS-native scheduling; no Kubernetes control plane to reason about.
Team is standardized on Kubernetes APIs and tooling Amazon EKS The stem naming Kubernetes, kubectl, or existing manifests is the whole signal.
Keep a fleet at the right size and replace unhealthy instances Amazon EC2 Auto Scaling Health checks plus min/max/desired capacity — the self-healing half of most resilient designs.
Keep average CPU (or request count) at a target Amazon EC2 Auto Scaling A target-tracking policy; step scaling is for staged thresholds.
Traffic follows a known daily or weekly pattern Amazon EC2 Auto Scaling Scheduled scaling warms capacity before the spike rather than chasing it.
Absorb a spike so a slow consumer never drops work Amazon SQS A buffer between producer and consumer: the queue grows instead of the consumer failing.
Messages must be processed in order, exactly once SQS FIFO queues Standard queues are at-least-once and best-effort ordered; FIFO is the discriminator.
Park messages a consumer keeps failing to process SQS dead-letter queues A poison message stops blocking the queue and becomes debuggable.
One event must reach several independent subscribers at once Amazon SNS Pub/sub fan-out. "Notify multiple systems simultaneously" is SNS, not SQS.
Coordinate a multi-step workflow with branching, retries, and error handling AWS Step Functions State machines replace the chained-Lambda answer whenever the stem describes steps or approvals.
Find which service in a request chain is slow AWS X-Ray Distributed tracing across services; CloudWatch shows the symptom, X-Ray shows the hop.
Thousands of queued compute jobs with capacity provisioned automatically AWS Batch Managed job queues on top of EC2 or Fargate — often paired with Spot for cost.
AWS services running inside your own data center for latency or data residency AWS Outposts "Must stay on premises" plus "native AWS APIs" is Outposts.
Full control over the OS, kernel, or a licensed appliance Amazon EC2 When the stem needs the machine itself, managed compute is ruled out.

Storage

Object, file, or block first — then how fast it must come back, then how cheap it must be.

When you see… Think…
Durable storage for any amount of unstructured data Amazon S3 Eleven nines of durability; the default answer for objects, backups, and data lakes.
Static website or single-page app served cheaply Amazon S3 Front it with CloudFront when the stem also wants TLS, a custom domain, or edge caching.
Access pattern is unknown or changes over time S3 Intelligent-Tiering Shifts objects between tiers automatically with no retrieval fee — the "we do not know" answer.
Data is hot for 30 days, then rarely touched S3 Lifecycle rules A known, age-based pattern is a lifecycle transition, not Intelligent-Tiering.
Archive read less than once a year, hours to restore is acceptable S3 Glacier Deep Archive The cheapest tier. If the stem tolerates hours, anything faster is over-spending.
Archive that must come back in milliseconds but is rarely read S3 Glacier Instant Retrieval Archive pricing without the wait; Flexible Retrieval takes minutes to hours.
Recover an object someone overwrote or deleted S3 Versioning Previous versions survive overwrites and deletes; add MFA delete to protect the versions themselves.
Same objects must exist in a second Region S3 Cross-Region Replication Asynchronous replication for latency, compliance, or regional DR. Versioning must be on.
Boot volume, or block storage for one instance Amazon EBS Single-instance, single-AZ; snapshots back it up incrementally to S3.
Guaranteed sustained IOPS for a latency-sensitive database Amazon EBS Provisioned IOPS (io1/io2). gp3 sets IOPS independently of size but does not promise the same sustained floor.
Cheapest block storage for large sequential logs or streaming data Amazon EBS Throughput-optimized HDD (st1) — and neither HDD type can be a boot volume.
Many Linux instances mount the same file system at once Amazon EFS Elastic NFS across AZs. "Shared" plus "POSIX" is always EFS.
Windows application needs a native SMB share joined to Active Directory Amazon FSx for Windows File Server SMB rules EFS out; lift-and-shift Windows workloads land here.
HPC scratch storage with extreme throughput, linked to S3 Amazon FSx for Lustre The high-performance-computing file system, with an S3 data repository association.
On-premises app needs an NFS/SMB share, iSCSI volume, or virtual tape backed by AWS AWS Storage Gateway A hybrid appliance presenting cloud storage in the protocol the legacy app already speaks.
One-off or scheduled bulk copy of an on-premises dataset into AWS AWS DataSync A transfer job, not a permanent presentation layer — that distinction separates it from Storage Gateway.
Partners upload files over SFTP, FTPS, or FTP straight into S3 AWS Transfer Family Managed protocol endpoints so the partner never changes their client.

Database

Relational or not; then read scaling versus failover, which is the single most reliably tested distinction in this domain.

When you see… Think…
Relational engine with automatic failover to another AZ Amazon RDS Multi-AZ A synchronous standby you cannot read from. It buys availability, never throughput.
Read traffic is swamping the primary Amazon RDS read replicas Asynchronous replicas serve reads and can be promoted; that is scaling, not HA.
MySQL or PostgreSQL compatibility with cloud-native speed and durability Amazon Aurora Six storage copies across three AZs and up to fifteen low-lag read replicas.
Relational workload that is intermittent, spiky, or hard to predict Amazon Aurora Serverless v2 Capacity scales in place instead of provisioning for the peak.
Relational reads in a second Region, promotable fast for DR Amazon Aurora Global Database Cross-Region replication with typically sub-second lag and a secondary Region promotable in about a minute.
Key-value or document access at any scale with no servers Amazon DynamoDB Single-digit-millisecond reads; no joins, no fixed schema, no capacity planning on demand.
NoSQL table written to from multiple Regions at once DynamoDB global tables Multi-Region, multi-active replication built into the table.
DynamoDB reads must drop from milliseconds to microseconds DynamoDB Accelerator (DAX) A DynamoDB-only cache with automatic invalidation — no application-side cache logic.
Restore a table to any second within the last 35 days DynamoDB point-in-time recovery A rolling 35-day window; on-demand backups cover anything older.
Cache in front of a database, session store, or leaderboard Amazon ElastiCache Managed Redis or Memcached at microsecond latency — a cache, never the system of record.
Lambda or a bursty app is exhausting database connections Amazon RDS Proxy Pools and reuses connections, and holds them open through a failover.
Complex analytical SQL over terabytes, BI dashboards, OLAP Amazon Redshift Columnar warehouse. "Analytics" over a relational schema means Redshift, not RDS.
Move a database into AWS with almost no downtime AWS DMS Continuous replication keeps the source live until cutover.
Move from Oracle or SQL Server to Aurora or PostgreSQL AWS DMS Schema Conversion Tool Heterogeneous migrations need schema conversion first, then DMS moves the data.
High-volume time-series or IoT telemetry Amazon Timestream Purpose-built for timestamped metrics; a relational table is the wrong shape.
Automated relational backups retained for weeks Amazon RDS Automated backup retention tops out at 35 days; manual snapshots persist until you delete them.

Analytics

The recurring tell is whether anything has to be running when nobody is querying.

When you see… Think…
Ad-hoc SQL over files already in S3, nothing to provision Amazon Athena Serverless and billed per byte scanned — partitioning and columnar formats are how stems ask you to cut that bill.
Discover schemas in S3 and make them queryable AWS Glue Crawlers populate the Data Catalog that Athena, EMR, and Redshift all read.
Serverless ETL to reshape or convert data formats AWS Glue Managed ETL jobs with no cluster to size.
Real-time ingest that several consumers can replay Amazon Kinesis Data Streams Shard-based ordering with a retention window — replay is what rules a queue out.
Spark, Hadoop, or Hive clusters Amazon EMR When the stem names the framework, it wants the managed cluster, not a serverless query engine.
Central, fine-grained table and column permissions across a data lake AWS Lake Formation Layers governed permissions over Glue instead of hand-writing bucket policies.

Management, Governance, and Cost

Cost questions are answered by commitment shape: how long, how flexible, and how interruptible the workload is.

When you see… Think…
Metrics, logs, alarms, and dashboards Amazon CloudWatch Operational telemetry. CloudTrail answers "who"; CloudWatch answers "how is it behaving".
Trigger scaling or a notification when a metric crosses a threshold CloudWatch alarms The trigger behind nearly every auto scaling and notification design.
Break the bill down by service, account, or tag; forecast next month AWS Cost Explorer Retrospective analysis and forecasting — reporting, not enforcement.
Alert when spend crosses, or is forecast to cross, a threshold AWS Budgets Thresholds and actions. "Notify me before we overspend" is Budgets, not Cost Explorer.
Steady compute spend, deepest discount, keep instance flexibility AWS Savings Plans Commit to a dollar-per-hour and stay flexible across family, size, Region, Fargate, and Lambda.
Unchanging instance family and Region for one or three years EC2 Reserved Instances The locked-configuration commitment; Savings Plans win whenever the stem wants flexibility.
Interruptible, fault-tolerant work at the lowest possible price EC2 Spot Instances Up to about 90% off with a two-minute interruption notice. Never for a stateful, must-finish workload.
Unpredictable, short-lived, or brand-new workload EC2 On-Demand Instances No commitment while the usage pattern is still being measured.
Automated checks for idle resources, open security groups, and quota headroom AWS Trusted Advisor Best-practice checks across cost, performance, security, fault tolerance, and limits.
Hitting a service limit and needing a higher one AWS Service Quotas One console to view limits, request increases, and alarm before you hit them.
Take S3 traffic off the NAT gateway to cut data-processing charges VPC Gateway Endpoints Free, and it removes both the NAT processing fee and the internet path.
Downloaders should pay the data transfer for your bucket S3 Requester Pays Shifts request and transfer cost to the requesting account.
Attribute spend back to a team, project, or environment AWS Cost Explorer Cost allocation tags plus grouping — the reason tagging shows up in cost stems.

The look-alikes

Each of these pairs shows up as two technically-plausible options in the same question. Memorize the split, not the services.

CloudTrail vs. CloudWatch vs. Config

AWS CloudTrail
Who made the API call, and when.
Amazon CloudWatch
How the resource is performing right now, and alarms on it.
AWS Config
What the resource was configured like over time, and whether that breaks a rule.

SQS vs. SNS

Amazon SQS
One consumer group pulls work at its own pace; the queue absorbs the spike.
Amazon SNS
One message must be pushed to several independent subscribers at once.

Cognito vs. IAM Identity Center

Amazon Cognito
Your application's end users — customers signing in to your app.
AWS IAM Identity Center
Your workforce — employees signing in to AWS accounts.

Gateway endpoint vs. Interface endpoint

VPC Gateway Endpoints
S3 or DynamoDB, free, added as a route-table entry.
AWS PrivateLink
Any other AWS or partner service, via an ENI, billed hourly plus per GB.

VPC peering vs. Transit Gateway

VPC Peering
A handful of VPCs; non-transitive, and no hourly charge.
AWS Transit Gateway
Many VPCs and on-premises links; transitive routing beats a growing mesh.

CloudFront vs. Global Accelerator

Amazon CloudFront
Cacheable HTTP(S) content served from the edge.
AWS Global Accelerator
Non-HTTP protocols, static IPs, or failover measured in seconds.

ALB vs. NLB vs. GWLB

Application Load Balancer
HTTP(S) routed by path, host, or header.
Network Load Balancer
TCP/UDP, extreme throughput, static IP, or source-IP preservation.
Gateway Load Balancer
Third-party inspection appliances inserted transparently.

S3 vs. EFS vs. EBS vs. FSx

Amazon S3
Objects reached over an API; no file system semantics needed.
Amazon EFS
A POSIX file system many Linux instances mount at once.
Amazon EBS
A block device for one instance, in one AZ.
Amazon FSx
Windows SMB, or Lustre for HPC.

Glacier Instant vs. Flexible vs. Deep Archive

S3 Glacier Instant Retrieval
Rarely read, but must come back in milliseconds.
S3 Glacier Flexible Retrieval
Minutes to hours is fine, and bulk restores are free.
S3 Glacier Deep Archive
Read less than once a year; hours to restore, cheapest per GB.

Multi-AZ vs. read replica

Amazon RDS Multi-AZ
Availability: a synchronous standby that takes over, and serves no reads.
Amazon RDS read replicas
Throughput: asynchronous copies that serve reads and can be promoted.

ElastiCache vs. DAX

Amazon ElastiCache
A general cache in front of any database, or a session store.
DynamoDB Accelerator (DAX)
DynamoDB specifically, with invalidation handled for you.

Redshift vs. Athena vs. EMR

Amazon Redshift
Sustained, complex warehouse queries against loaded data.
Amazon Athena
Occasional SQL straight against S3, with nothing running in between.
Amazon EMR
The stem names Spark, Hadoop, or Hive.

Direct Connect vs. Site-to-Site VPN

AWS Direct Connect
Consistent bandwidth and latency matter, and weeks of lead time are acceptable.
AWS Site-to-Site VPN
It has to work today, cheaply, or serve as the backup path.

Security group vs. network ACL

Amazon VPC Security Groups
Per-instance, stateful, allow rules only.
Amazon VPC Network ACLs
Per-subnet, stateless, and the only place you can write a deny.

Savings Plans vs. Reserved Instances vs. Spot

AWS Savings Plans
Steady spend, but the instance mix will change.
EC2 Reserved Instances
The configuration is fixed for the whole term.
EC2 Spot Instances
The work can be interrupted and restarted.

GuardDuty vs. Macie

Amazon GuardDuty
Threat activity: compromised credentials, mining, suspicious DNS.
Amazon Macie
Sensitive data at rest in S3: PII discovery and classification.

Storage Gateway vs. DataSync

AWS Storage Gateway
On-premises apps keep using NFS, SMB, iSCSI, or tape, permanently.
AWS DataSync
A transfer job that moves a dataset and then finishes.

Qualifiers that break the tie

When two answers are both technically correct, this clause — usually the last sentence of the stem — is what decides between them.

Qualifier in the stem What it rules in or out
Least operational overhead / fully managed Prefer the serverless or managed option: Fargate over EC2, Aurora Serverless over self-tuned instances, DynamoDB over a database you patch.
Most cost-effective The cheapest option that still meets every stated requirement — not the cheapest option outright.
No application changes / lift and shift Rule out anything that means a rewrite: keep the protocol (SMB, NFS, SFTP) and the engine the app already speaks.
Cannot lose any data / RPO of zero Synchronous replication only — a Multi-AZ standby, not an asynchronous replica or a nightly backup.
Recover within minutes / RTO in minutes Something must already be running: warm standby or active-active, never backup-and-restore.
Must not traverse the public internet VPC endpoints, PrivateLink, or Direct Connect — and a NAT gateway does not qualify.
Highly available At least two Availability Zones. An answer pinned to one AZ is wrong regardless of its other merits.
Automatically / without manual intervention Rule out any answer whose first step is a human: no manual snapshots, no manual failover, no ticket.
Decouple A queue or a topic belongs in the answer — SQS to buffer, SNS to fan out.
Unpredictable or spiky traffic On-demand and elastic: Auto Scaling, Lambda, DynamoDB on-demand capacity, Aurora Serverless.
Existing corporate directory Federation, not new IAM users: IAM Identity Center with an external identity source.
Encrypted with keys we control and audit KMS with a customer managed key, not the default AWS managed key.
Global users complaining about latency CloudFront for HTTP content, Global Accelerator for everything else, latency-based routing for Region choice.
Retain for N years for compliance Lifecycle into Glacier, and add Object Lock if the stem says the records cannot be altered.
