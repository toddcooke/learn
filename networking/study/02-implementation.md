## Routing Technologies & High Availability

### Static Routing vs. Dynamic Routing Protocols

A static route is a path to a destination network typed into a router's routing table by hand; it stays exactly as configured until an administrator edits it again, and because there's no protocol overhead or route computation involved, it's predictable and lightweight — but it also can't react on its own if the underlying link fails, so a human (or a floating static route configured with a higher administrative distance as a backup) has to notice and fix the problem. Dynamic routing protocols solve that by letting routers exchange reachability information with each other automatically and recompute paths whenever the topology changes, without any manual edits. Different dynamic protocols use fundamentally different mechanisms to decide what counts as the best path and how they discover it: distance-vector protocols share routing information mainly with directly connected neighbors and often rely on hop count, link-state protocols flood topology information so every router can independently compute shortest paths, and path-vector protocols track the sequence of networks a route has crossed rather than a simple hop count — differences covered in more detail below, alongside the separate mechanism a router uses to choose between routes offered by two different protocols at once.

### Interior Gateway Protocols: OSPF & EIGRP

OSPF (Open Shortest Path First), defined in RFC 2328, is a link-state interior gateway protocol (IGP) — meaning it is designed to run inside a single autonomous system rather than between separate organizations' networks — in which every router floods information about its own directly connected links to the rest of its area, and each router independently runs a shortest-path-first calculation against that shared link-state database to build its own view of the best routes. EIGRP (Enhanced Interior Gateway Routing Protocol), defined in RFC 7868, is Cisco's advanced distance-vector protocol: instead of flooding a full topology map, it exchanges routing information directly with its neighbors and uses the Diffusing Update Algorithm (DUAL) to calculate loop-free paths and pre-compute backup routes before a failure ever happens, converging far faster than a classic distance-vector protocol like RIP that has to wait and recompute after a change. Both OSPF and EIGRP are interior gateway protocols in the sense that they are built to run inside one organization's own network rather than between separately administered ones, which is the dividing line that separates them from BGP.

### BGP: Path-Vector Routing Between Autonomous Systems

BGP (Border Gateway Protocol), defined in RFC 4271, is an exterior gateway protocol built to route between separately administered autonomous systems (ASes) — most visibly, the ISPs, cloud providers, and large organizations that together make up the public internet — rather than inside a single organization's own network the way OSPF and EIGRP do. BGP is classified as a path-vector protocol: instead of calculating a shortest path from raw link costs the way a link-state protocol does, it selects a route based largely on the AS path attribute, the literal sequence of autonomous systems a route announcement has already crossed, along with several other configurable attributes an administrator can use to influence which path gets preferred. Because it operates between organizations rather than inside one, BGP also emphasizes policy control over pure efficiency — an organization can prefer a specific path for business reasons, like a paid transit agreement, even when a shorter path technically exists, something the purely metric-driven interior protocols are not designed to do.

### Route Selection: Administrative Distance vs. Metric

Administrative distance (AD) and metric solve two different problems, at two different stages of route selection — a distinction worth knowing precisely. AD is what a router checks first, to decide which routing protocol to believe when two different protocols each offer a route to the exact same destination network; it is a per-protocol trust ranking with no relationship to actual path quality, and the default Cisco values run, from most to least trusted: directly connected interfaces at 0, static routes at 1, EIGRP (internal) at 90, OSPF at 110, and RIP at 120 — lower always wins, so a router holding both an OSPF route and an EIGRP route to the same destination installs the EIGRP one purely because 90 beats 110, regardless of which path is actually shorter or faster. Metric is a separate calculation that only comes into play once AD has already narrowed the field down to a single protocol: it is how that one protocol picks the best of several possible paths among its own routes, using whatever criteria that protocol defines — hop count for RIP, a composite of bandwidth and delay for EIGRP, or cumulative link cost for OSPF. In short, AD picks a winner between protocols; metric picks a winner within one protocol, and the two values are never compared against each other.

### NAT and PAT

Network Address Translation (NAT), described in RFC 3022 under the label traditional NAT, rewrites the source (or destination) IP address in a packet's header as it crosses a router — most commonly so that hosts using private, non-routable RFC 1918 addresses can reach the public internet through one or more public addresses. RFC 3022 splits traditional NAT into two variants: Basic NAT, which translates only the IP address and needs one public address for every internal host active at the same time (a one-to-one mapping), and Network Address Port Translation (NAPT) — the mechanism vendors commonly market as PAT (Port Address Translation) — which additionally rewrites the source port number, so many internal hosts can share a single public IP address at once by each receiving a unique port mapping. PAT is by far the more common deployment in home and small-business routers, since it lets an entire private network reach the internet through the one public address an ISP typically hands out.

### First Hop Redundancy: HSRP vs. VRRP & Virtual IP

A First Hop Redundancy Protocol (FHRP) lets two or more routers share a single virtual IP address that end hosts are configured to use as their default gateway, so if the router actually forwarding traffic fails, another router in the group takes over that same virtual IP transparently — from a host's perspective, the gateway address never changes, only which physical router answers to it. HSRP (Hot Standby Router Protocol), defined in RFC 2281, is Cisco-proprietary: it elects one active router to forward traffic for the group, designates at least one standby router as backup, and can leave any others in a listening state, and it operates by sending hello packets to the multicast address 224.0.0.2 over UDP port 1985. VRRP (Virtual Router Redundancy Protocol), defined in RFC 5798, is the open IETF standard equivalent — it uses Master and Backup instead of active/standby, and it identifies its virtual router with a virtual MAC address in the 00-00-5E-00-01-{VRID} range (hex) for IPv4. HSRP and VRRP are not interoperable even though they do the same job: a router running one cannot participate in a group running the other, because the two protocols use different multicast addresses, different packet formats, and different virtual MAC ranges — meaning a network standardizing on FHRP redundancy has to pick one protocol consistently across all of its gateway routers.

## Switching & the Layer 2/3 Boundary

### VLANs and the Switch Virtual Interface (SVI)

A VLAN (Virtual LAN) logically divides a single physical switch, or a group of switches, into multiple separate broadcast domains, so devices assigned to different VLANs can't reach each other directly at Layer 2 even when they're plugged into the very same physical switch — traffic between VLANs has to be routed, exactly as if the VLANs were separate physical networks. This is how one physical switch infrastructure can serve, for example, a voice VLAN, a guest VLAN, and a data VLAN as fully isolated broadcast domains without running separate cabling for each. Because separate VLANs need something to route between them, a Layer 3 switch can be given a Switch Virtual Interface (SVI) — a virtual Layer 3 interface tied to one specific VLAN that acts as that VLAN's default gateway, letting the switch itself perform inter-VLAN routing instead of sending that traffic out to a dedicated external router, an older design sometimes called router-on-a-stick when a physical router is used for the same job instead.

### 802.1Q Tagging and Trunking

An access port on a switch belongs to exactly one VLAN and carries untagged frames, so the devices plugged into it have no idea VLANs even exist. A trunk port instead is built to carry traffic for multiple VLANs over one physical link — commonly the links between switches, or between a switch and a router — and to keep frames from different VLANs distinguishable as they cross that shared link, IEEE 802.1Q inserts a 4-byte tag into the Ethernet frame header carrying a 12-bit VLAN ID field, which allows up to 4,094 usable VLAN IDs (0 and 4095 are reserved). One VLAN, the native VLAN, is the exception: 802.1Q lets it cross a trunk untagged by convention, which helps with compatibility for older equipment but is also a well-known security consideration, since a native VLAN mismatch between the two ends of a trunk lets frames leak between VLANs that were never supposed to reach each other.

### Link Aggregation: LACP and EtherChannel

Link aggregation combines several physical switch ports into a single logical link, so traffic between two switches (or a switch and a server) can use the combined bandwidth of every member link and survive the failure of any one of them without an outage — the alternative, treating each physical link separately, would force Spanning Tree to block all but one of them to prevent a loop. EtherChannel is Cisco's umbrella term for this kind of bundling. LACP (Link Aggregation Control Protocol), standardized as part of IEEE 802.1AX, is the open, vendor-neutral protocol that negotiates which ports join a bundle and continuously confirms both ends still agree on the configuration, as opposed to a purely static, manually configured bundle with no negotiation at all — the difference matters because LACP can automatically detect and pull a misconfigured or failed link out of the bundle, while a static bundle simply forwards on whatever ports are configured, correct or not.

### Spanning Tree Fundamentals: Loop Prevention & Port Roles

Spanning Tree Protocol (STP, IEEE 802.1D) exists to solve a problem that redundant switch links create on their own: when switches are wired with multiple paths between them for resiliency, those same redundant paths form Layer 2 loops that would circulate broadcast frames forever, since Ethernet frames carry no TTL-like hop limit to stop them. STP prevents that by electing a single root switch (the one with the lowest bridge ID) for the whole topology, and then every other switch computes one loop-free active path back to it: one port per switch becomes the root port, the best path toward the root; one port per network segment becomes the designated port, the one that forwards for that segment; and any other port that would complete a loop is put into a blocking state, discarding frames without disabling the physical link entirely, so it stays ready to take over if the active path fails without any re-cabling or re-enabling — though, as the next topic covers, classic STP still walks it through intermediate states on the way to forwarding.

### Port States, RSTP & Convergence Timers

A blocked STP port does not jump straight to forwarding the moment it is needed — it steps through listening (learning topology information but still not forwarding) and learning (starting to build its MAC address table but still not forwarding) before finally reaching forwarding, a sequence whose default timers (a 20-second max-age plus two 15-second forward-delay periods) can add up to as much as 50 seconds of downtime in a worst-case failover. RSTP (Rapid STP, IEEE 802.1w), deployed on modern Cisco switches as Rapid PVST+, collapses that listening/learning wait through a direct handshake between neighboring switches, converging in a few seconds instead of tens of seconds. IEEE 802.1w is itself a paywalled standard with no free canonical text, but as standard vocabulary taught alongside it: RSTP merges blocking and listening into a single discarding state, and it adds an alternate port role — a pre-computed backup path to the root that a switch can promote straight to forwarding if the current root port fails, skipping discarding and learning entirely.

### MTU, Jumbo Frames & Path MTU Discovery

The Maximum Transmission Unit (MTU) is the largest frame size a network link will carry without fragmenting it, and RFC 894 set the baseline for wired Ethernet at 1500 bytes for the IP datagram carried inside the frame — a limit that has stuck around for decades since so much wired networking gear still assumes it by default. Jumbo frames raise that ceiling, commonly to around 9000 bytes, which cuts overhead for large transfers since fewer frames means fewer headers and fewer per-frame processing interrupts, but it only works if every device along the path — NICs, switches, and any routers in between — is configured to accept the larger size; a jumbo frame reaching a device still set to the standard 1500-byte MTU gets fragmented or dropped. RFC 1191 defines Path MTU Discovery (PMTUD) to handle that kind of mismatch automatically: a sending host sets the Don't Fragment (DF) bit on its packets, and if a router along the path can't forward one without fragmenting it, that router discards the packet and returns an ICMP message reporting the MTU of the link that couldn't take it, letting the source shrink its packet size for that path instead of the packet silently disappearing.

## Wireless Devices & Security

### Frequency Bands & Non-Overlapping Channels

Wi-Fi (IEEE 802.11, itself a paywalled standard with no free canonical text) radios operate in unlicensed frequency bands — 2.4GHz, 5GHz, and most recently 6GHz — with very different channel behavior. The 2.4GHz band is numbered up to channel 14, but each channel is only 5MHz apart while an actual transmission occupies roughly 22MHz of spectrum, so adjacent channels overlap and interfere with one another; only channels 1, 6, and 11 sit far enough apart to run at full power in the same area without stepping on each other, which is why 1/6/11 is the standard non-overlapping channel plan taught for 2.4GHz despite channels being numbered as high as 14 (only 1-11 are even legal to use in the US). The 5GHz band has far more usable spectrum and, as a result, more non-overlapping 20MHz channels — but several of its sub-bands (the UNII-2 and UNII-2 Extended ranges) are shared with weather and military radar systems, so access points using those channels must implement Dynamic Frequency Selection (DFS): continuously monitoring for radar signals and vacating the channel within seconds if one is detected, automatically moving connected clients to a different channel. The 6GHz band, opened to Wi-Fi with Wi-Fi 6E (the extension of Wi-Fi 6 / 802.11ax into that spectrum), adds the most non-overlapping channels of the three and stays the least congested because only the newest clients can use it — the running tradeoff across the bands being that lower frequencies reach farther and penetrate walls better, while higher frequencies offer more clean, uncrowded spectrum at shorter range. Band steering puts that spread to work: a multi-band access point detects clients capable of 5GHz or 6GHz and nudges them up off the crowded 2.4GHz band, reserving it for the devices that support nothing else.

### SSID, BSSID, ESSID & Network Types

The SSID (Service Set Identifier) is the human-readable network name a wireless client sees and picks from, such as HomeNetwork or CorpWiFi. The BSSID (Basic Service Set Identifier) is the actual MAC address of the specific radio, or access point, providing that SSID — every individual radio has its own unique BSSID even when several access points all broadcast the identical SSID as part of one larger wireless network, which is exactly how a client roams between access points without the network name ever changing. The ESSID (Extended Service Set Identifier) refers to that broader set of access points sharing one SSID and working together to cover a larger area than any single radio could reach alone. Wireless networks also come in two structural types: infrastructure mode, the standard deployment where every client associates through a central access point that typically also bridges the wireless side to the wired network, and ad hoc mode, where devices connect directly to each other peer-to-peer with no access point involved at all — used far less often today, since infrastructure mode covers essentially every enterprise and home deployment.

### WPA2 vs. WPA3

WPA2 secures a wireless network using AES in CCMP mode for encryption and integrity, and it establishes the session key through a four-way handshake between the client and access point once the client has already proven it knows the pre-shared key (PSK), or has authenticated through an Enterprise back end. That handshake is also WPA2's biggest weak point: an attacker who captures it can attempt an offline dictionary or brute-force attack against the PSK with no further interaction with the live network at all, and the KRACK (Key Reinstallation Attack) vulnerability disclosed in 2017 showed the handshake itself could be manipulated to force reuse of an encryption key, undermining the encryption regardless of password strength. WPA3 targets that offline-cracking weakness by replacing the four-way PSK handshake with SAE (Simultaneous Authentication of Equals, also called the Dragonfly handshake): critically, WPA3 still uses a pre-shared key for personal and home deployments — it does not eliminate PSKs — but SAE changes how that key gets verified, forcing an attacker to interact with the live access point for every single password guess instead of capturing one handshake and cracking it offline at whatever speed their hardware allows, which makes brute-forcing even a weak password dramatically slower and far easier to detect.

### Authentication Modes: PSK vs. Enterprise (RADIUS & EAP)

PSK (pre-shared key) mode is the simplest wireless authentication model: every client on the network proves it belongs by knowing one shared passphrase, which is easy to deploy but doesn't identify which specific user or device actually connected, and revoking access for one person means changing the passphrase for everyone else on the network. Enterprise mode instead authenticates each user or device individually against a back-end AAA (authentication, authorization, and accounting) server, typically using RADIUS, defined in RFC 2865, as the protocol carrying the authentication exchange itself, with EAP (Extensible Authentication Protocol, RFC 3748) providing the flexible framework for whichever specific authentication method is actually used inside that exchange — a certificate, a username and password pair, or another credential type, depending on the EAP variant configured. RADIUS runs over UDP, historically on port 1645 before being standardized on port 1812 by RFC 2865, and it is this back-end authentication step, not the encryption protocol itself, that lets Enterprise mode identify and individually revoke exactly one compromised user without touching anyone else's credentials.

### Guest Networks & WLAN Security Guidance

A guest network is a separate SSID, usually PSK-secured with a simple or rotating passphrase, kept isolated from the main internal network (often through its own dedicated VLAN) so visitors get internet access with no path to internal resources — a practical, everyday application of the same segmentation idea VLANs provide more broadly elsewhere on the network. NIST's WLAN security publication, SP 800-153, frames the whole problem as a lifecycle rather than a single setting to get right: it recommends securing every component involved in a wireless deployment — the client devices, the access points, and any wireless switches — starting at initial design and deployment and continuing through ongoing monitoring, rather than leaning on any one control, like a strong PSK or Enterprise authentication, in isolation from the rest.

### Antenna Types

An omnidirectional antenna radiates its signal roughly equally in every horizontal direction around it, which is why it is the default choice built into most consumer access points and routers — it covers a roughly circular area without needing to be aimed at anything in particular. A directional (unidirectional) antenna instead concentrates its signal into a narrower beam pointed at one specific target, trading coverage in every other direction for significantly more range and signal strength in that one direction; a Yagi antenna is a common directional type used for long point-to-point links, such as connecting two buildings or extending coverage to one distant area, while a parabolic (dish) antenna concentrates the signal even further for the longest-range point-to-point links. The choice comes down to the coverage shape actually needed: broad, even coverage for a room or floor calls for an omnidirectional antenna, while a targeted long-distance link calls for a directional one.

## Physical Installation Factors

### IDF and MDF

The MDF (Main Distribution Frame) is the central point where a building's or campus's outside cabling and core networking equipment come together — typically where the internet handoff, core switches, and primary patch panels are located. An IDF (Intermediate Distribution Frame) is a secondary wiring closet, usually one per floor or wing in a larger building, that connects back to the MDF and distributes cabling out to the end-user devices in its local area, so no single cable run has to stretch further across a building than necessary. IDF/MDF terminology comes from structured cabling standards (TIA/EIA-568) that are paywalled ANSI documents with no free canonical text, so this is treated as standard networking vocabulary rather than a citable spec — but the underlying idea is a simple hub-and-spoke cabling design: one central distribution point (the MDF) feeding multiple local distribution points (IDFs), each of which fans out to the actual wall jacks nearby.

### Rack Sizing & Standards

Server and network equipment racks follow a standardized width and height unit defined by EIA-310, another paywalled ANSI/EIA document with no free canonical source, so the exact numbers are worth stating directly as standard facts rather than tracing to a citable text: a standard rack accepts equipment whose front panel — faceplate plus the mounting flanges that bolt to the rails — spans 19 inches across its outer edges (the opening between the rails is slightly narrower, about 17.75 inches), and vertical space inside it is measured in rack units (U), where 1U equals 1.75 inches. Equipment is described by how many U it occupies — a 1U switch is a slim, single-unit device, while a 4U server is a much taller chassis — and the total usable capacity of a rack, commonly 42U or 48U for a full-height rack, is simply the sum of everything mounted inside it. Getting this right matters for planning: a network closet needs both the correct rack width to physically accept 19-inch equipment and enough vertical U space for everything that has to be mounted, with room left over for future growth.

### Structured Cabling & Category Standards

Structured cabling standardizes how a building's network cabling is designed and installed — permanent horizontal cable runs from a wiring closet out to each wall jack, vertical backbone cabling connecting an MDF to its IDFs, and defined limits on how far a single cable run can stretch before signal quality degrades too much to rely on. Twisted-pair copper cabling is further split into numbered categories with different supported speeds and maximum distances — common examples include Cat 5e (up to 1 Gbps), Cat 6 (up to 10 Gbps over shorter distances), and Cat 6a (10 Gbps over the full standard distance, thanks to added shielding that suppresses alien crosstalk — interference leaking in from separate cables nearby, not between the pairs inside one cable). All of this comes from the TIA/EIA-568 structured cabling standards, paywalled ANSI/TIA/EIA documents with no free canonical source, so the category names and general design pattern are treated here as standard structured-cabling vocabulary rather than a citable RFC or spec.

### Patch Panels & Cable Management

A patch panel is a fixed panel of ports, mounted in a rack, where the permanent cable runs from wall jacks throughout a building terminate on one side; a short patch cable then connects each of those ports to a switch port on the other side, which keeps the switch itself out of the way of general wear and lets an installer change which jack maps to which switch port just by moving a short patch cable, instead of re-running a cable through the whole building. Good cable management builds on that same structured design: labeling both ends of every run, dressing cables with velcro rather than tight zip ties that can pinch and damage the copper pairs inside, and keeping patch cords no longer than necessary. None of this is just cosmetic — it directly affects how quickly a technician can trace and fix a problem during troubleshooting, since a poorly labeled or tangled patch panel turns a two-minute fix into a much longer one.

### Power: UPS and PDU

A UPS (Uninterruptible Power Supply) sits between the utility power feed and networking or server equipment, holding a charged battery that takes over instantly if utility power fails, keeping equipment running through a brief outage and giving it enough time to shut down cleanly during a longer one instead of losing power abruptly. A PDU (Power Distribution Unit) covers a different piece of the same problem: rather than providing backup power, it's a rack-mounted device, conceptually similar to a heavy-duty power strip, that distributes power from one or more upstream feeds out to the many individual devices in a rack, and higher-end PDUs add remote monitoring or even per-outlet remote power cycling, letting an administrator reboot one misbehaving device without a site visit. In a well-designed installation, a UPS or a facility-wide generator typically feeds a PDU, which in turn feeds the individual devices mounted in that rack — redundancy and backup power sit further upstream, while the PDU's job is purely distributing that power locally.

### Environmental Factors: Temperature, Humidity & Fire Suppression

Network and server equipment generates heat continuously and is sensitive to the environment around it, so a data center or wiring closet needs active, dedicated climate control rather than relying on a building's general HVAC system — sustained high temperature is one of the most common causes of premature hardware failure, and most equipment has a manufacturer-specified operating temperature and humidity range an installation is expected to stay within. Humidity matters in both directions: too much promotes condensation and corrosion on components, while too little raises the risk of electrostatic discharge (ESD) damaging sensitive electronics, so facilities aim for a controlled middle range rather than simply keeping things cool and dry. Fire suppression in a room full of expensive electronics also can't rely on the water sprinklers used in general office space, since water damages equipment about as badly as fire does; data centers instead typically use clean-agent gas suppression systems that displace oxygen or interrupt the chemical combustion reaction without leaving a damaging residue, putting the fire out while protecting the hardware around it.
