  • options -var · -var-file · -refresh=false · -replace=ADDR · -target=ADDR (exceptional use only)
  • apply -auto-approve · a saved plan file is itself the approval

Sensitive Data

  • sensitive (0.15+) redacts in CLI and UI and propagates through expressions — but is still stored in state
  • ephemeral (1.10+) variables, child module outputs, and the ephemeral block — never stored
  • write-only (1.11+) password_wo arguments, paired with a _wo_version state does track
  • Vault mint short-lived credentials at run time instead of storing them

Meta-Arguments

  • count — N identical instances, count.index, addressed [0]; value must be known pre-apply
  • for_each — map or set of strings, each.key / each.value, addressed ["k"]; stable keys survive removals
  • provider — pick an aliased configuration, provider = aws.west
  • depends_on — hidden dependencies only; literal references; makes plans conservative
  • lifecycle — create_before_destroy (propagates to dependencies), prevent_destroy, ignore_changes (or all), replace_triggered_by, plus precondition / postcondition

Types & Expressions

  • Primitive string, number, bool — converted between automatically
  • Collection list(...), map(...), set(...) — one element type
  • Structural object({k=type}), tuple([types]) — mixed types; extra object attributes discarded
  • for [for s in l : upper(s) if s != ""] → tuple; {for s in l : s => upper(s)} → object
  • splat var.list[*].id — lists/sets/tuples only, not for_each maps
  • conditional cond ? a : b — both results must share a type
  • dynamic generates repeatable nested blocks from a collection; cannot generate lifecycle
  • functions ~100 built-ins; none user-defined; provider functions as provider::name::fn; try in terraform console

Variable Precedence

  1. -var / -var-file on the CLI, and HCP Terraform variables
  2. *.auto.tfvars[.json], lexical order
  3. terraform.tfvars.json
  4. terraform.tfvars
  5. TF_VAR_ environment variables
  6. the variable's default

Undeclared: env var ignored, tfvars file warns, -var errors. Child modules take values only from their module block.

Providers & Versions

  • Source [HOST/]NAMESPACE/TYPE, default host registry.terraform.io
  • Local name unique per module; resource type prefix picks the provider by default
  • Constraints = != > >= < <= ~>; ~> 1.0.4 allows 1.0.5 not 1.1.0; ~> 1.1 allows 1.2 not 2.0
  • Guidance root modules pin with ~>; reusable modules set only a minimum
  • Lock file .terraform.lock.hcl — providers only, with checksums; commit it; init -upgrade to move
  • Tiers Official · Partner Premier · Partner · Community · Archived

State & Backends

  • Why map config to real objects · keep dependency metadata for destroy · cache attributes for speed · share across a team
  • Local default; terraform.tfstate + .backup; locks via system APIs; runs locally
  • backend block one only, inside terraform; no variables or expressions; re-init on change; never with a cloud block
  • Locking automatic where supported; -lock=false and force-unlock <ID> are last resorts
  • Drift found on refresh; accept it with apply -refresh-only, revert it with a normal apply
  • Refactor prefer moved / removed blocks over state mv / state rm
  • Secrets state holds them in cleartext — never commit it; use a remote encrypted backend

Modules

  • Sources local ./path · registry NS/NAME/PROVIDER · private HOST/NS/NAME/PROVIDER · Git (?ref=) · HTTP archive · S3/GCS; // selects a subdirectory; literal strings only
  • Versions version works for registry modules only; not covered by the lock file, so pin exactly for reproducibility
  • Scope values in via inputs, out via outputs, nothing else; providers inherit from the parent
  • Shape keep the tree flat and pass dependencies in

HCP Terraform

  • Workspaces mandatory; hold configuration, variables, state, run history, state versions; the unit of RBAC
  • Projects group workspaces and scope team permissions; every workspace is in exactly one
  • Execution Remote (default) · Local (state only) · Agent (private networks)
  • Variables Terraform or environment, optionally sensitive or HCL; variable sets reuse them across workspaces
  • Run triggers up to 20 source workspaces; queue on their successful apply
  • Governance policy sets (Sentinel, OPA, Terraform policy) checked against the plan · cost estimation · private registry · explorer · change requests · health assessments (drift detection + continuous validation, needs remote or agent mode)
  • CLI cloud block + terraform login, then init migrates state; dynamic credentials replace stored ones via OIDC
